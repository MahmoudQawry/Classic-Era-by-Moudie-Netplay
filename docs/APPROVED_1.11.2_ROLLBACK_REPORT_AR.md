## 2. المكوّنات المؤكدة داخل النسخة المعتمدة

يحتوي APK على **ست نوى محاكاة**، جميعها ARM64:

| النظام | المكتبة الموجودة فعليًا |
|---|---|
| NES / Famicom | `fceumm_libretro_android.so` |
| PlayStation 1 | `pcsx_rearmed_libretro_android.so` |
| PSP | `ppsspp_libretro_android.so` |
| Sega Genesis | `genesis_plus_gx_libretro_android.so` |
| Nintendo 64 | `parallel_n64_libretro_android.so` |
| PlayStation 2 | `play_libretro_android.so` |

كما يحتوي على جسر Play!، وHermes، ومكتبة WebRTC الأصلية، و3 ملفات DEX. حزمة JavaScript هي `assets/index.android.bundle`، وحجمها `3,265,940` بايت، وبصمتها موثقة في ملف المرجع.

**لا يصح حذف N64 أو PS2 باعتبارهما إضافات غير متعلقة بالإصدار:** كلاهما موجود داخل APK الذي اختاره المستخدم. وبالمثل، غياب ملفات `server/` أو الاختبارات عن APK لا يعني أنها زائدة؛ تطبيق الهاتف لا يضم عادةً مصدر خادمه أو اختبارات تطويره.

## 3. لماذا لم يُنفَّذ استبدال المصدر أو الحذف الشامل؟

فُحص سجل الفروع البعيدة والوسوم ومراجع رؤوس **28 طلب دمج**، بما مجموعه **893 commit** وقت البحث. لم يُعثر على تغيير محفوظ لنسخة `1.11.2` في ملفات الإصدار أو على مرجع مصدر يمكن إثبات أنه أنتج APK المرسل. هذا وصف لحدود الأدلة المتاحة، وليس ادعاءً بأن المصدر غير موجود على جهاز آخر أو في مستودع آخر.

المصدر الذي كانت عليه الجلسة (`5cc28cb`) يختلف عن APK المعتمد في نقاط مؤكدة:

| البند | APK المعتمد | المصدر الحالي قبل الاستعادة |
|---|---|---|
| الإصدار | `1.11.2` | `1.0.1` |
| versionCode | `53` | `2` |
| المعماريات | ARM64 فقط | ARMv7 + ARM64 + x86 + x86_64 |
| الحد الأدنى | API 24 | API 26 |
| التوقيع | شهادة Debug ثابتة داخل الملف | workflow ينشئ مفتاح CI مؤقتًا لكل بناء |

ملف APK يتضمن مخرجات مترجمة: DEX وHermes bytecode ومكتبات أصلية. **ليس نسخة من المستودع الأصلي**؛ ولا يتيح وحده استرجاع مصدر TypeScript/Kotlin حرفيًا أو تحديد مصدر الخادم وقاعدة البيانات والاعتماديات المقفلة التي بُني معها.

لذلك لم يتم:

- اختيار `v1.11.0` لمجرد تقارب الحجم؛ ليس هو الملف الذي اعتمده المستخدم.
- إرجاع المستودع إلى بناء سبتمبر آخر ثم تغيير اسمه إلى `1.11.2`.
- حذف وظائف أو خادم أو ملفات دعم استنادًا إلى غيابها عن APK فقط.
- نسبة قائمة إصلاحات تاريخية للإصدار `1.11.2` دون مصدر أو changelog يثبتها.

## 4. إجراءات السحب والحماية

1. **حُذف الإصدار المعيب** `android-test-latest` وملف APK ذي الحجم `124,339,371` بايت (**118.58 MiB**) ووسمه البعيد في الخطوة السابقة. أُعيد التحقق من عدم ظهوره ضمن الإصدارات.
2. حُفظت نسخة غير معدّلة من APK المعتمد في **مسودة خاصة غير منشورة** للمرجعية؛ لم يُنشر إصدار جديد يدّعي تطابق المصدر معه.
3. أُزيلت مهام الفحص المؤقتة من ملفات فرع العمل بعد استخدامها. لم تُضف ملفات APK أو نوى محاكاة مولّدة أو `node_modules` إلى Git.
4. جُهِّز تعديل `.github/workflows/android-build-reset.yml` ليصبح تشغيله يدويًا فقط، مع إيقاف job البناء صراحةً أثناء انتظار المصدر، وخفض صلاحية `contents` إلى القراءة.
5. أُزيل نشر Release واستبدال APK بواسطة `--clobber`. حتى عند إعادة تمكين البناء لاحقًا، يبقى ناتجه artifact للمراجعة وليس إصدارًا منشورًا تلقائيًا.
6. أُضيفت 3 اختبارات تحمي إعدادات الإيقاف وبصمة المرجع وتمنع إسناد commit تخميني له.

**نطاق التطبيق:** تغييرات الحماية موجودة على فرع الجلسة `arena/01a0e8c3-classic-era-by-moudie-netplay`؛ لا تؤثر في workflow فرع `main` إلا بعد دمجها. تعطيل workflow على مستوى إعدادات GitHub رُفض سابقًا بخطأ `403 Resource not accessible by integration`. يلزم تعطيله من واجهة GitHub أو إعادة ربط GitHub في Arena بصلاحية Actions المناسبة إذا كان المطلوب منع تشغيل نسخه القديمة على جميع الفروع أيضًا.

## 5. تقييم المستودع والفحوص الفعلية

**التقييم الأساسي:** المشكلة المؤكدة ليست الحجم وحده؛ هناك ضعف في ربط الملف المنشور بمصدر ثابت. الناشر السابق كان يستبدل الملف تحت وسم واحد، بينما يبقى اسم الإصدار ومرجع المصدر القديم دون تحديث. كما أن خفض `versionCode` وتغيير شهادة التوقيع يمكن أن يعطلا مسار التحديث فوق نسخ مثبّتة سابقًا.

الفحوص التالية أُجريت على **المصدر الحالي مع تعديلات الحماية فقط**، ولا تعني أنه مصدر APK المعتمد:

| الفحص | النتيجة |
|---|---|
| تثبيت الاعتماديات باستخدام `pnpm@9.12.0 install --frozen-lockfile` | ناجح، دون تعديل lockfile |
| TypeScript: `pnpm check` | ناجح |
| Vitest | **135 ناجحًا، 2 متجاوزان، 0 فاشل** |
| ESLint: `pnpm lint` | ناجح |
| بناء الخادم: `pnpm build` | ناجح |
| سلامة ZIP وتوقيع APK المعتمد | ناجحان في مهمة الفحص |
| بناء Android مطابق للملف المعتمد | **لم يُنجز؛ المصدر المطابق غير محدد** |
| تثبيت ولعب وصوت على جهاز فعلي | **لم يُختبر** |

ملاحظات تحتاج مراجعة بعد العثور على المصدر:

- شهادة Debug مناسبة للاختبار، وليست أساسًا آمنًا لنشر إنتاجي مستمر.
- APK يتضمن أذونات مثل الكاميرا والتخزين القديم و`SYSTEM_ALERT_WINDOW` إلى جانب أذونات الصوت والشبكة. ينبغي تقييم ضرورتها لاحقًا، لكن لم تُغيَّر خلسةً داخل النسخة المعتمدة.
- وجود النوى الست لا يثبت نجاح كل محاكي أو مزامنته على الأجهزة. اختبارات إعادة الاتصال وتبديل الشبكة والصوت وملفات الحفظ ما زالت مطلوبة.
- نجاح الاختبارات الآلية الحالية لا يتعارض مع بلاغ المستخدم عن أخطاء تشغيل كثيرة؛ فحص النصوص والأنواع لا يغطي تجربة اللعب الفعلية كاملةً.

## 6. المطلوب لإتمام الاستعادة دون تخمين

يكفي توفير واحد من الآتي:

- ملف ZIP **لمصدر المشروع الذي بُني منه هذا APK**، دون `node_modules` أو ملفات أسرار أو مفاتيح توقيع.
- رقم commit أو رابط الفرع/المستودع الصحيح.
- رابط مهمة البناء أو جلسة التطوير التي أنتجت `Classic-Era-1.11.2-arm64-test.apk`، إذا احتوت على مرجع مصدر قابل للاسترجاع.

بعد تحديد المصدر: تُستعاد شجرته على فرع الجلسة دون محو تاريخ Git، وتُزال فقط الإضافات التي يثبت أنها خارج هذا الإصدار، ثم يُعاد الفحص والبناء وتوثيق أي فروق عن APK المرجعي. إذا لم يتوفر المصدر، يمكن الاتفاق على إعادة بناء تقريبية من مرجع سابق، **لكن لا يجوز وصفها بأنها مطابقة حرفيًا للنسخة المعتمدة**.
